# Research Snapshot Policy

Research snapshots are refreshed before a major milestone or when a decision's
key upstream constraint changes. Each snapshot records date, query/selection
method, repository commit or release where practical, maintenance/archive
state, license, and primary scientific or platform sources.

Stars are discovery metadata only. Adoption requires evidence from CameraMan's
code boundary, maintenance cost, license compatibility, hardware measurements,
quality tests, and release constraints. A new dependency must solve an approved
feature or measured bottleneck; repository popularity is never sufficient.

For time-sensitive claims, refresh official docs and current releases. Preserve
the previous dated snapshot so decisions remain auditable, and record which
recommendation or ADR changed because of the new evidence.
